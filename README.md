# MaxAutopost

**Бот для автоматического кросспостинга между Telegram и MAX.** Пересылает посты из Telegram-канала или группы в канал/группу мессенджера MAX — и обратно. Поддерживает текст, фото, видео, аудио, файлы и альбомы. Гибкие фильтры по пользователю и теме форума позволяют настроить пересылку под любой кейс.

> Уже используется для кросспостинга в реальном канале.

## Возможности

- **Двусторонняя пересылка**: Telegram → MAX и MAX → Telegram (направление задаётся для каждой пары).
- **Все типы контента**: текст, фото, видео, аудио, документы и альбомы (медиагруппы).
- **Сохранение форматирования**: HTML-разметка переносится, при несовместимости — автоматический откат на обычный текст.
- **Фильтры**: whitelist по `user_id` и по теме форума (`message_thread_id`).
- **Каналы и группы**: поддержка как каналов, так и супергрупп с темами.
- **Простая настройка**: один `.env` и один `channels.json`, без редактирования кода.
- **Безопасность**: проверка входящих вебхуков по секрету (генерируется автоматически, если не задан).
- **Деплой в один шаг**: готовый `Dockerfile` и `docker-compose.yml`.

## Как это работает

Бот работает на **вебхуках** (не polling). При старте он:

1. Регистрирует вебхук в Telegram и подписку на вебхук в MAX.
2. Поднимает HTTP-сервер, который слушает два пути:
   - `TELEGRAM_WEBHOOK_PATH` (по умолчанию `/webhook/tg`)
   - `MAX_WEBHOOK_PATH` (по умолчанию `/webhook/max`)

Поэтому боту нужен **публичный HTTPS-адрес** (`WEBHOOK_URL`). Обычно перед ботом ставят реверс-прокси (nginx / Caddy / Traefik), который терминирует TLS и проксирует запросы на `WEBHOOK_HOST:WEBHOOK_PORT`.

## Требования

- Python **3.11+** (или Docker)
- Бот в Telegram ([@BotFather](https://t.me/BotFather)) — токен
- Бот в MAX — токен
- Публичный домен с HTTPS для приёма вебхуков

## Быстрый старт

```bash
git clone https://github.com/agosset15/MaxAutopost
cd MaxAutopost

cp example.env .env              # заполните токены и WEBHOOK_URL
cp channels.example.json channels.json   # пропишите свои id

docker-compose up -d             # запуск
```

## Настройка `.env`

Скопируйте `example.env` в `.env` и заполните:

| Переменная | Обяз. | По умолчанию | Описание |
|---|:---:|---|---|
| `MAX_BOT_TOKEN` | ✅ | — | Токен бота в MAX |
| `TELEGRAM_BOT_TOKEN` | ✅ | — | Токен бота в Telegram |
| `WEBHOOK_URL` | ✅ | — | Публичный **базовый** HTTPS-URL, напр. `https://example.com` (без пути) |
| `WEBHOOK_SECRET` | — | случайный | Секрет для проверки входящих вебхуков (5–256 симв., `A-Z a-z 0-9 _ -`). Если пусто — генерируется при запуске |
| `TELEGRAM_WEBHOOK_PATH` | — | `/webhook/tg` | Путь для вебхука Telegram |
| `MAX_WEBHOOK_PATH` | — | `/webhook/max` | Путь для вебхука MAX |
| `WEBHOOK_HOST` | — | `0.0.0.0` | Адрес, на котором слушает сервер |
| `WEBHOOK_PORT` | — | `9154` | Порт сервера |
| `PROXY_URL` | — | — | SOCKS/HTTP-прокси для Telegram (если API заблокирован) |
| `CHANNELS_FILE` | — | `channels.json` | Путь к файлу сопоставления |

> `WEBHOOK_URL` указывайте **без пути** — пути добавляются автоматически из `TELEGRAM_WEBHOOK_PATH` / `MAX_WEBHOOK_PATH`.

Минимальный `.env`:

```env
MAX_BOT_TOKEN=ваш_токен_max
TELEGRAM_BOT_TOKEN=ваш_токен_telegram
WEBHOOK_URL=https://example.com
WEBHOOK_SECRET=придумайте_длинную_строку
```

## Сопоставление каналов (`channels.json`)

Скопируйте `channels.example.json` в `channels.json` — это массив записей, каждая описывает одну пару «источник → назначение».

### Канал

```json
{ "tg_id": -1001000000001, "max_id": -71000000000001 }
```

Бот должен быть **администратором** канала.

### Группа / супергруппа

```json
{
  "type": "group",
  "tg_id": -1001000000003,
  "max_id": -71000000000003,
  "allowed_user_ids": [123456789, 987654321],
  "allowed_thread_ids": [12, 45]
}
```

| Поле | Обяз. | Описание |
|---|:---:|---|
| `tg_id` | ✅ | ID Telegram-чата (канала или группы) |
| `max_id` | ✅ | ID канала/группы в MAX — куда пересылать |
| `type` | — | `"channel"` (по умолчанию) или `"group"` |
| `direction` | — | `"tg_to_max"` (по умолчанию) или `"max_to_tg"` |
| `allowed_user_ids` | — | whitelist по `from_user.id` |
| `allowed_thread_ids` | — | whitelist по теме форума |

> **Privacy Mode**: для работы в группах отключите его у бота через [@BotFather](https://t.me/BotFather) → `/setprivacy` → **Disable**, иначе обычные сообщения не дойдут до бота.

### Фильтры

- **`allowed_user_ids`** — если задан, пересылаются только сообщения от перечисленных пользователей. Пусто/нет поля — фильтр выключен. Анонимные админы (без `from_user`) при заданном whitelist игнорируются.
- **`allowed_thread_ids`** — если задан, пересылаются только сообщения из указанных тем. Особые значения:
  - `0` — только из **General** (`message_thread_id == None`);
  - `1` — все темы, **кроме** General.

### Обратное направление (MAX → Telegram)

Добавьте запись с `"direction": "max_to_tg"`:

```json
{
  "type": "channel",
  "tg_id": -1001000000004,
  "max_id": -71000000000004,
  "direction": "max_to_tg"
}
```

- Пересылаются текст, изображения, видео, аудио и файлы (включая альбомы).
- Telegram-бот должен быть **администратором** целевого канала/группы.
- Каждая пара **односторонняя**. Не создавайте две записи с одной парой `(tg_id, max_id)` в противоположных направлениях — будет зацикливание.
- `allowed_user_ids` / `allowed_thread_ids` в обратном направлении не применяются.

## Запуск в Docker (рекомендуется)

Требуется Docker и Docker Compose. Убедитесь, что заполнены `.env` и `channels.json`.

```bash
docker-compose up -d          # запуск в фоне
docker-compose logs -f        # логи в реальном времени
docker-compose down           # остановка
docker-compose up -d --build  # пересборка после изменения кода
```

> Изменения в `.env` применяются при перезапуске контейнера — пересборка образа не требуется.

## Локальный запуск

```bash
# Python 3.11+
python -m venv venv
# Windows
venv\Scripts\activate
# Linux/macOS
source venv/bin/activate

pip install -r requirements.txt
python main.py
```

## Частые проблемы

- **Бот не получает сообщения из группы** — не отключён Privacy Mode (см. выше).
- **Telegram не шлёт апдейты** — `WEBHOOK_URL` недоступен извне по HTTPS или указан с путём; должен быть публичный базовый адрес.
- **Сообщения не уходят в MAX/Telegram** — бот не админ целевого канала/группы.
- **Зацикливание** — две зеркальные записи на одну пару `(tg_id, max_id)`.
- **Telegram API недоступен** — задайте `PROXY_URL`.
